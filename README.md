# 室内靶场 · Shooting Range

一个最简 Web 3D 第一人称靶场：站在固定射击位上，用鼠标锁定视角，
对着远处静止的人形标靶开火。当前主角是蜂巢小队 B（爆破兵）——
身高 2.4m 的强化士兵，第一人称视角，坐在头盔里操作整套外骨骼武器系统。

## 🧠 项目背景与发展讨论记录（重要，新会话先读这节）

> 以下内容来自"我和用户"的设计讨论，用于防止后续新增内容时丢失项目来龙去脉。

### 1. 原始设定（用户讲的故事）

- 主角小队：**A B C D E** 五人，全是**经过机能强化的特种兵**，
  身高约 **2.4~2.5m**，身穿先进外骨骼、携带先进武器。
- 分工：**A 突击 / B 爆破 / C 工程 / D 医疗 / E 通信**。
- 项目目标：把五人**以第一人称方式**做进这个室内靶场；当前先完成 **B**。
- 玩家视角设定在角色的**头盔/外骨骼里**，之后要支持**在五人之间切换角色**；
  因为只看得到第一人称武器和特效，所以**不需要做复杂的人体/装备建模**。
- 关键设计原则：**枪就是角色的脸**——每个角色的差异感主要来自第一人称武器、
  射击手感、特效、HUD 风格，而不是全身模型。

### 2. B 的装备设定（用户原话 + 我的解读）

- **双肩「蜂巢」导弹**：每肩约 **60 发**，合计约 120 发；导弹很小、数量极多，
  每一发都有制导，开火后像小蜜蜂一样飞向目标，**路径没什么规律**。
- **后背左侧「电磁轨道炮」**：平时竖着贴在背上，使用时通过**液压系统 + 两个电机**
  伸出并平放在身体左侧。
- **后背右侧「六管机枪」**：类似火神炮/加特林，**固定机构和使用方式与轨道炮一样**，
  平时在背上，使用时平放身体右侧。
- **手持榴弹机枪**：主武器，默认一直拿着。
- **可见性规则**：
  - 默认只看得见手里的榴弹机枪；
  - 轨道炮 / 六管**只有在使用状态时可见**（平时在背上完全看不到）；
  - 蜂巢**始终没有模型**，只有使用时能看到**肩部火焰**。
- **互斥规则**：
  - 榴弹机枪 ↔ 轨道炮/六管 **互斥**（背挂武器展开时，榴弹机枪自动隐藏）；
  - 轨道炮与六管之间**不互斥**（可同时展开、同时开火）；
  - 蜂巢是肩部系统，不受互斥影响，任何状态都能用。
- **弹药与冷却**：**弹药不限**，但各系统有独立冷却（蜂巢齐射/轮射冷却、
  轨道炮充能+冷却、六管 spin-up 预热）。
- **HUD 是重点**：AI 辅助瞄准、自动锁定（四套武器都享受）、弹药量、通信、
  敌人位置等。敌人先用训练标靶占位，**之后可能做移动标靶/虚拟敌人**，
  所以底层做成可扩展目标列表（`targetRegistry`）。

### 3. 由 AI 拍板、用户暂时默认的控制/数值（可随时改）

- **控制**：`1` 收回背挂 · `2` 轨道炮展开/收起 · `3` 六管展开/收起 ·
  `Q` 轨道炮充能射击 · **左键** 当前主武器 · **右键** 蜂巢（长按轮射 / 双击齐射）。
- **蜂巢**：齐射 = 两肩各 10 发共 20，冷却 8s；长按轮射逐发交替，停止后冷却 1.5s。
- **轨道炮**：充能时间约 500ms，未满 220ms 松手取消；冷却 1.8s；命中 +15。
- **六管**：spin-up 0.45s 后才开火，0.05s/发持续射击；命中 +1。
- **榴弹**：射速约 230ms/发；命中 +5。
- 标靶**被打中后倒下 2.4s 再自动立起**；倒下动画由弹体系统直接驱动。
- **当前不可移动**（固定射击位），移动是之后的扩展点。

### 5. 本机器/环境的坑（重要）

- **Node 已切到 Windows**：`node_modules` 里只有 `@rolldown/binding-win32-x64-msvc`，
  Linux 的 `node` 无法直接 `pnpm build`（会报找不到 `rolldown-binding.linux-x64-gnu.node`）。
  在本环境构建需用 **Windows Node**（`C:\Users\bowen\AppData\Local\nvm\v24.14.0\node.exe`），
  例如：
  ```cmd
  cmd /c "cd /d E:\teeny-tiny-little-projects && C:\Users\bowen\AppData\Local\nvm\v24.14.0\node.exe node_modules\typescript\bin\tsc -b && C:\Users\bowen\AppData\Local\nvm\v24.14.0\node.exe node_modules\vite\bin\vite.js build"
  ```
- **Vite dev 服务文件监听不稳定**：在这个环境里改代码后 HMR 经常不生效，
  需要**重启 dev server** 才能看到最新代码。
- **React `<StrictMode>` 已移除**：R3F 开发态下会重复挂载 Target（出现重叠标靶副本，
  导致倒下动画看起来失效）；去掉后正常。
- **无头验证用 Windows `chrome-headless-shell` + SwiftShader**：软件渲染 WebGL，
  R3F 帧循环时断时续，射击命中/动画的静态截图不可靠；**实际浏览器正常**。
- 验证完记得**停掉 dev server 和无头 Chrome**（很吃 CPU）。

## 当前主角：B · 爆破兵

- **体型**：2.4m 强化士兵，第一人称视角固定在 `(0, 2.35, 0)`，当前不可移动。
- **武器系统（第一批 + 第二批）**：
  - **榴弹机枪**：默认手持，左键开火，榴弹有重力抛物线 + 爆炸特效。
  - **蜂巢导弹**：双肩 60+60 发，无限弹药但有独立冷却；
    - 右键**长按** = 轮射（左右肩交替逐发）
    - 右键**双击** = 齐射（两肩各 10 发，共 20）
    - 导弹带不规则“蜂群”弹道，自动寻的锁定目标，命中为小爆炸。
  - **电磁轨道炮**（背部左侧）：平时不可见，**2 键**展开到身体左侧；
    **Q（或仅轨道炮展开时左键）长按充能、松开发射**，单发高伤 + 电浆曳光。
  - **六管机枪**（背部右侧）：平时不可见，**3 键**展开到身体右侧；
    展开后**左键按住**先 spin-up 预热，随后持续射击曳光弹。
  - **互斥规则**：榴弹机枪与轨道炮/六管互斥（背挂武器展开时榴弹机枪自动隐藏），
    两件背挂武器之间**不互斥**，可同时展开、同时开火。

## 当前主角：A · 突击兵（第三批已实装）

- **定位**：与 B 的「重火力平台」形成对照——轻快、持续 DPS、激光辅助的突击手。
- **主武器 · 大弹夹轻机枪（LMG）**：
  - 120 发大方弹匣，左键按住持续射击（约 0.085s/发），`R` 换弹；
  - **激光瞄具**：枪口红色激光直指锁定目标/准星落点，命中前可见瞄准线与光斑；
  - **独特瞄准系统**：右键按住 = 稳定瞄准（激光收束 + 散布收敛）；
  - **热度机制**：连续射击抬高枪管热度，散布变大；停火缓慢冷却，HUD 实时显示。
- **多类型手雷**：`G` 投掷、`T` 切换；碎片（+8）/ 闪光（+4，不推倒）/ 燃烧（+6）。
  - **特效区分**：碎片 = 大范围碎片爆；闪光 = 白色大爆闪 + 全屏白屏；燃烧 = 小爆点 + 引燃延迟的持续火焰带。
- **双肩激光反导（CIWS）**：与 B 蜂巢同位置，自动追踪并激光标记最近目标，
  被标记目标自动锁定角度放宽（辅助锁定）；未来敌方导弹接入时可扩展硬拦截。
- **HUD**：A 专属红色锐角战术终端（无玻璃整板、无 ECG 大面板），
  组件与布局均与 B 的「青蓝玻璃板」刻意区分：左侧武器/手雷/CIWS 三块，
  右侧战术网 + **心率/生命体征** + 状态，左下外骨骼 + 小队通信，中央锐角准星。

### A 专属 · 四足机器人 Q-01（第一版）

- **状态机**：`STOWED ─Q─▶ AUTO ─F─▶ REMOTE`；任何状态按 `Q`：遥控时先退出全屏并还原 A 视角，
  机器人**走回 A 背后（BACK_SPOT）再回收**，不再原地缩小。遥控链路会自动剔除 A 主体
  （`OPERATOR CULL: ON`），以换取干净视野（设定解释：A 主体不在机器人链路里渲染）。
- **AUTO**：航点巡逻 + 到点扫描 + 发现目标后接近至射击环带、自动机枪射击/导弹齐射；
  AI 状态（PATROL/SCAN/MOVE_TO/ENGAGE/HOLD）写入 `droneStore` 供 HUD 显示。
  **移动逻辑集中在 `moveToward` + `aiStateRef`，未来换寻路/避障系统只替换这一段。**
- **REMOTE**：全屏接管（相机移到机器人头部），WASD 沿镜头方向移动、Space 四足小跳、
  左键开火、1/2 切换武器、F 交还 AI。
- **武器**：背部「哨兵」机枪塔（热量槽）+ 两侧「蜂针」微型导弹舱（左右各 4 发，冷却 6s，
  冷却结束后自动补满，避免长时间弹药不足）。
- **HUD**：AUTO 时 A HUD 右侧显示 `DronePanel`（LINK/POWER/SPEED/AI/MG/MSL/SENSOR）；
  REMOTE 时切到全屏 `DroneHud`（机器人观瞄 + 机身状态 + 武器 + 雷达 + 操作提示）。

- **E 模式**：`LMB` AR-05 · `R` 换弹 · `G` TRI 信标 · `T` EMP 干扰弹 ·
  `Q` RAVEN 部署/收回 · `F` RELAY/SWEEP/STRIKE 循环 · `V` 链路视角（`WASD` 飞行 /
  `Space` 上升 / `Ctrl` 下降）· `1/2` MG/MSL
- **N**：夜视滤镜（绿色）
- 左上角 leva 面板：调靶距、鼠标灵敏度

## HUD（战术头盔界面 · 科幻玻璃板风格）

- **整体**：一整块“写满东西的玻璃板”，暗夜蓝底 + 青色荧光，英文信息，
  既有真实反馈也有装饰性模块（参照 Anima Digitalis 的 ECG 模型）。
- **中央**：准星 + 锁定环 + AIM ASSIST 状态 + 得分。
- **顶栏**：罗盘条（AZ/EL 实时跟随视角）、坐标、小队标识、NV 状态。
- **左侧**：生理状态（含 **ECG 实时波形**、心率/血氧/血压/体温/肾上腺素）、
  外骨骼状态（PWR/ARMOR/HYD/INTEG/伺服/关节）。
- **右侧**：武器系统（榴弹/轨道炮/六管/蜂巢 + 冷却 + **武器完好度 WEAR**）、
  战术雷达 + 目标列表。
- **左下**：小队通信流 + 环境读数；**右下**：状态胶囊 + 装饰滚动数据。
- **夜视**：`N` 键切换绿色滤镜（Canvas CSS filter + HUD 绿色调）。
- **通用组件（全员共用，未来角色也复用）**：
  - `BioPanel`（心率/ECG/血氧/体温/肾上腺素）、`ExoPanel`（外骨骼能量/装甲/液压/完整度）、
    `CommsPanel`（小队通信流 + 队友位置/状态）、`ScreenFlash`（爆炸白闪）、
    `CompassStrip`（罗盘）、`Radar`（战术雷达）、`EnemyMarkers`（屏幕敌标）、`DecoStrip`（装饰数据）。
  - 通用组件只保证「功能一致」，**风格/位置/组件组合按角色 Layout 各自编排**。
- **A 专属 HUD**：红色锐角战术终端——无玻璃整板，非对称斜切面板，
  专属组件（热度条/手雷快捷栏/CIWS 面板/锐角准星），布局与 B 完全区分；
  后续 C/D/E 也按「独立 Layout + 主题 + 专属组件 + 共用小件」方式实现。
- **敌人位置**：当前以训练标靶为敌人占位，底层为可扩展目标列表，
  后续可直接接入移动标靶 / 虚拟敌人。

## 小队与换人（架构）

- **单页面点卡片换人**：底部 A–E 小队卡（`hud/SquadSelector.tsx`），点击切换当前角色；
  卡片显示代号/角色/READY或WIP，当前角色高亮使用各自主题色。
- **每个角色 HUD 是独立组件**：`hud/layouts/` 下每个角色一个 Layout，`hud/Hud.tsx`
  只负责按 `activeRoleId` 加载对应 Layout 并注入主题色（--hud-primary/secondary）。
- **每个角色武器独立挂载（配置驱动）**：`scene/squad/CharacterRig.tsx` 读取当前角色
  `config.weapons` 的 id 列表，从 `weapons/registry.ts` 取组件自动挂载，切换角色时自动清理武器状态；
  目前 B 完整（榴弹/蜂巢/轨道炮/六管）、A 已实装（LMG/手雷/激光反导），C/D/E 为 WIP 占位配置。
- **角色配置集中**：`squad/characters/` 每个角色一个配置文件
  （id/标题/英文角色/主题色/武器清单/hud 布局），后续加人=加配置+加布局+加武器。

## 实现要点

- **固定第一人称**：相机锁定在射击位，只有鼠标相对移动，不做位移移动。
- **程序化场景**：房间、人形标靶、全部武器 ViewModel 都用 Three.js 基础几何体拼接。
- **弹体系统**：`combat/Projectiles.tsx` 统一管理榴弹 / 蜂巢导弹 / 轨道炮弹 / 六管曳光 / 爆炸特效。
- **背挂武器展开**：Railgun/Minigun 平时在背上不可见，展开时带液压动画从画面两侧滑入；
  展开状态与主武器互斥，两者之间可并存。
- **目标注册表**：`combat/targetRegistry.ts` 注册标靶位置与包围盒，
  锁定、HUD 投影、命中判定共用一套数据，方便以后多目标扩展。
- **标靶倒下**：命中事件直接驱动标靶 2.4s 倒下动画，不依赖 React 订阅。
